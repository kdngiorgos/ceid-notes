```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void)
{
    int i, tmp;

    pid_t pid[4];

    for (i=0; i<4; i++) {
        pid[i] = fork();
        if (pid[i] == 0) {
            break;
        }
    }

    if (pid[0] != 0 && pid[1] != 0 && pid[2] != 0 && pid[3] != 0) {
        // That's the father, it waits for all the childs
        printf("I'm the father [pid: %d, ppid: %d]\n", getpid(), getppid());
        for(i=0; i<4; i++) {
            wait(&tmp);
        }
    } else {
        // That's the child, it print its pid, its parent pid and exits
        printf("I'm one of the children [pid: %d, ppid: %d]\n", getpid(), getppid());
    }

    return 0;
}
```

    ## Θέμα 1

    *Αξιοπιστία: λύθηκε με βάση τις φωτογραφίες του θέματος· μία λύση AI*

    Στην εικόνα IMG_20260122_152138_386.jpg ο κώδικας 2 διαβάζεται καθαρά: περιέχει `if (pid > 0) { ... wait(NULL); break; }`.

    **Τι κάνει ο Κώδικας 1 (αριστερά):**
    - Ο αρχικός πατέρας εκτελεί έναν βρόχο 4 επαναλήψεων ($i=0, 1, 2, 3$). Σε κάθε επανάληψη καλεί την `fork()`.
    - Αν `pid[i] == 0` (το παιδί), εκτελεί `break` και βγαίνει αμέσως από τον βρόχο χωρίς να καλέσει άλλες `fork()`.
    - Μόνο ο αρχικός γονέας συνεχίζει στον βρόχο και δημιουργεί συνολικά 4 παιδιά.
    - Ο γονέας εκτυπώνει το μήνυμά του και εκτελεί 4 φορές την `wait(&tmp)`, περιμένοντας όλα τα παιδιά του να τερματίσουν. Κάθε παιδί εκτυπώνει το pid του και το ppid του και τερματίζει.
    - Συνολικά δημιουργούνται 5 διεργασίες σε **αστεροειδή ιεραρχία («βεντάλια»)**: 1 κοινός πατέρας με 4 αδέλφια-παιδιά που εκτελούνται παράλληλα.

    **Τι κάνει ο Κώδικας 2 (δεξιά):**
    - Ο αρχικός γονέας καλεί την `fork()` στο $i=0$ και δημιουργεί ένα παιδί ($P_1$).
    - Επειδή για τον γονέα ισχύει `pid > 0`, εκτυπώνει τα στοιχεία (`Father = ..., Id = ..., Child = ...`), καλεί `wait(NULL)` περιμένοντας το παιδί του και κάνει `break` τερματίζοντας τον βρόχο.
    - Το παιδί $P_1$ έχει `pid == 0`, οπότε δεν μπαίνει στο `if (pid > 0)` και συνεχίζει στην επόμενη επανάληψη του βρόχου ($i=1$), όπου καλεί το ίδιο `fork()` δημιουργώντας ένα εγγόνι ($P_2$), εκτυπώνει, κάνει `wait(NULL)` και `break`.
    - Η διαδικασία αυτή επαναλαμβάνεται διαδοχικά για $N=4$ φορές.
    - Συνολικά δημιουργούνται 5 διεργασίες σε **γραμμική ιεραρχία (αλυσίδα διαδοχικών γενεών)**: $P_0 \to P_1 \to P_2 \to P_3 \to P_4$.

    **Βασικό σημείο στο οποίο διαφέρουν:**
    Το βασικό σημείο διαφοράς είναι η **δομή/ιεραρχία των παραγόμενων διεργασιών**:
    - Στον Κώδικα 1 το `break` εκτελείται από τα **παιδιά** (`if (pid[i] == 0) break`), με αποτέλεσμα ο ίδιος αρχικός γονέας να γεννά και τα 4 παιδιά (παράλληλη / αστεροειδής ιεραρχία 1 επιπέδου).
    - Στον Κώδικα 2 το `break` εκτελείται από τον εκάστοτε **γονέα** (`if (pid > 0) break`), ενώ το παιδί συνεχίζει τον βρόχο, με αποτέλεσμα κάθε διεργασία να γεννά μόνο 1 απόγονο (γραμμική ιεραρχία / αλυσίδα διεργασιών: πατέρας $\to$ παιδί $\to$ εγγονός $\to$ δισέγγονος $\to$ τρισέγγονος).

    ## Θέμα 4

    *Αξιοπιστία: λύθηκε με βάση τις φωτογραφίες του θέματος· μία λύση AI*

    Στην εικόνα IMG_20260122_152140_456.jpg ο πίνακας σελίδων διαβάζεται καθαρά (επιβεβαιώνεται και από την ταυτόσημη άσκηση του Σεπτεμβρίου 2025):
    - Σελίδα 0: Πλαίσιο 4, Bit = 0
    - Σελίδα 7: Πλαίσιο 15, Bit = 1
    - Σελίδα 15: Πλαίσιο 9, Bit = 1
    - Σελίδα 31: Πλαίσιο 15, Bit = 0

    Δεδομένα:
    - 32 σελίδες λογικής μνήμης $\implies 2^5 = 32$, άρα απαιτούνται 5 bits για τον αριθμό σελίδας ($p \in [0, 31]$).
    - Μέγεθος σελίδας $1024\text{ bytes} = 2^{10}\text{ bytes} \implies$ απαιτούνται 10 bits για το offset ($d \in [0, 1023]$).
    - Συνολικό μέγεθος λογικής διεύθυνσης: $5 + 10 = 15\text{ bits}$.
    - Εύρος έγκυρων λογικών διευθύνσεων: $0$ έως $2^{15} - 1 = 32767 = \text{7FFF}_{16}$.

    **Έλεγχος των προτάσεων:**
    - **(Α) Λάθος:** Με 14 bits καλύπτονται $2^{14} = 16384\text{ bytes}$ (16 σελίδες), ενώ η διεργασία έχει 32 σελίδες και απαιτεί 15 bits.
    - **(Β) Λάθος:** Η διεύθυνση $\text{FFFF}_{16} = 65535$ αντιστοιχεί στη σελίδα $\lfloor 65535 / 1024 \rfloor = 63$, η οποία υπερβαίνει το μέγιστο όριο των 32 σελίδων ($0..31$). Άρα δεν είναι έγκυρη λογική διεύθυνση της διεργασίας.
    - **(Γ) Λάθος:** Η διεύθυνση $\text{3CCC}_{16} = 15564_{10}$. Ο αριθμός σελίδας είναι $\lfloor 15564 / 1024 \rfloor = 15$ και το offset είναι $15564 \bmod 1024 = 204 = \text{0CC}_{16}$. Στον πίνακα, η σελίδα 15 έχει πλαίσιο 9 και bit 1. Η φυσική διεύθυνση είναι $9 \times 1024 + 204 = 9216 + 204 = 9420_{10} = \text{24CC}_{16}$ (και όχι $\text{9CCC}_{16}$).
    - **(Δ) Σωστή:** Η διεύθυνση $\text{7CCC}_{16} = 31948_{10}$. Ο αριθμός σελίδας είναι $\lfloor 31948 / 1024 \rfloor = 31$ και το offset είναι $31948 \bmod 1024 = 204 = \text{0CC}_{16}$. Η σελίδα 31 ανήκει στον λογικό χώρο της διεργασίας ($31 < 32$), αλλά στον πίνακα σελίδων έχει Έγκυρο/Άκυρο bit ίσο με 0. Επομένως, δεν είναι φορτωμένη στη φυσική μνήμη (θα προκαλέσει σφάλμα σελίδας / page fault).

    ## Θέμα 5

    *Αξιοπιστία: δύο ανεξάρτητες λύσεις συμφωνούν · εμπιστοσύνη λύτη: μέτρια*

    **(α) Αλγόριθμος αρτοποιείου (bakery) του Lamport για N διεργασίες** (το πλήθος στην εκφώνηση είναι δυσανάγνωστο, γράφεται γενικά για N). Κάθε διεργασία παίρνει «αριθμό» μεγαλύτερο από όλους τους υπάρχοντες· μπαίνει στην κρίσιμη περιοχή η διεργασία με τον μικρότερο αριθμό, με ισοπαλία να λύνεται από το μικρότερο id.

    ```
    shared: boolean choosing[N] = {false};  int number[N] = {0};

    process i:
      while (true) {
         choosing[i] = true;
         number[i] = 1 + max(number[0..N-1]);
         choosing[i] = false;
         for (j = 0; j < N; j++) {
            while (choosing[j]) ;                         // περίμενε να πάρει αριθμό ο j
            while (number[j] != 0 &&
                   (number[j] < number[i] ||
                   (number[j] == number[i] && j < i))) ;  // ο j έχει προτεραιότητα
         }
         /* ΚΡΙΣΙΜΗ ΠΕΡΙΟΧΗ */
         number[i] = 0;
         /* ΜΗ ΚΡΙΣΙΜΗ ΠΕΡΙΟΧΗ */
      }
    ```

    Το $choosing[j]$ εμποδίζει την περίπτωση να συγκριθούμε με διεργασία που ακόμα υπολογίζει τον αριθμό της.

    **(β) Pathname translation του /Users/[όνομα]/os/mmap.c → inode# του mmap.c** (τυπική διαδικασία UNIX):
    1. Ξεκινά από το inode της ρίζας (γνωστός, σταθερός αριθμός, π.χ. 2).
    2. Διαβάζεται το inode της ρίζας: έλεγχος ότι είναι κατάλογος και ότι υπάρχει δικαίωμα εκτέλεσης/αναζήτησης· διαβάζονται τα data blocks του καταλόγου και αναζητείται εγγραφή με όνομα `Users` → βρίσκεται inode# του `Users`.
    3. Διαβάζεται το inode του `Users` (έλεγχος κατάλογος + δικαιώματα), σαρώνονται τα blocks του και βρίσκεται η εγγραφή `[όνομα]` → inode#.
    4. Το ίδιο για τον κατάλογο `[όνομα]` → εγγραφή `os` → inode#.
    5. Το ίδιο για τον κατάλογο `os` → εγγραφή `mmap.c` → **inode# του αρχείου mmap.c** (έξοδος της διαδικασίας).

    Σε κάθε βήμα γίνονται 2 προσπελάσεις δίσκου (inode + data block(s) του καταλόγου, εκτός αν είναι στην cache)· συνολικά ~4 κατάλογοι. Αν κάποιο όνομα δεν βρεθεί ή λείπει δικαίωμα, η μετάφραση αποτυγχάνει.
