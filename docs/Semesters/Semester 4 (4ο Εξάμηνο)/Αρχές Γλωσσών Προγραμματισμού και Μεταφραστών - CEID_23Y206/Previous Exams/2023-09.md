    > Λύσεις που μεταφέρθηκαν από το παλιό συγκεντρωτικό αρχείο. Δεν έχουν επαληθευτεί· οι ασυμφωνίες με την εκφώνηση σημειώνονται στα warnings του αρχείου.

    **(α) Τελεστής Προσαύξησης & Τριαδικός Τελεστής:**

    - **Ανάλυση:**
      1. `++flag`: Η τιμή του `flag` αυξάνεται από -1 σε **0**.
      2. Στη C, το $0$ αντιστοιχεί σε λογικό **false**.
      3. Άρα εκτελείται ο δεύτερος κλάδος του τριαδικού τελεστή: `(var2 += 20)`.
      4. `var2` γίνεται $2 + 20 = \mathbf{22}$.
      5. Ο πρώτος κλάδος (`var1 -= 10`) **δεν** αποτιμάται (short-circuit), άρα `var1 = \mathbf{1}`.
      6. Η έκφραση επιστρέφει $22$, οπότε `c += 22` $\implies c = -1 + 22 = \mathbf{21}$.
    - **Τελικές τιμές:** `var1 = 1`, `var2 = 22`, `flag = 0`, `c = 21`.

    **(β) Μετατροπή For Loop σε Αναδρομική Συνάρτηση:**
    ```c
    int recursive_sum(int *A, int N) {
        if (N <= 0) {
            return 0;
        }
        return A[N - 1] + recursive_sum(A, N - 1);
    }
    ```

    ```python
    # Μενού διαθέσιμων πιάτων και τιμών
    menu = {
        "Χωριάτικη Σαλάτα": 6.5,
        "Μουσακάς": 9.0,
        "Σουβλάκι Μερίδα": 8.5,
        "Μπριζόλα": 10.0,

    }

    order = {}
    print("=== ΜΕΝΟΥ ΕΣΤΙΑΤΟΡΙΟΥ ===")
    for item, price in menu.items():

    # Παράδειγμα παραγγελίας
    order["Μουσακάς"] = 2
    order["Χωριάτικη Σαλάτα"] = 1
    order["Αναψυκτικό"] = 2

    # Υπολογισμός και εκτύπωση απόδειξης
    total_cost = 0.0
    print("
    === ΑΠΟΔΕΙΞΗ ΠΑΡΑΓΓΕΛΙΑΣ ===")
    for item, qty in order.items():
        cost = qty * menu[item]
        total_cost += cost
        print(f"{item} x {qty} = {cost:.2f}€")
    print(f"---------------------------
    ΣΥΝΟΛΙΚΟ ΚΟΣΤΟΣ: {total_cost:.2f}€")
    ```

    1. **Πρόθυμη Αποτίμηση (Eager / Applicative-Order Evaluation):**
       - Πρώτα αποτιμάται το όρισμα της `square`, δηλαδή το `sum [1:10]`.
       - `sum [1:10]` $\to 1 + \text{sum}[2:10] \to \dots \to 1 + 2 + \dots + 10 = 55$. (Απαιτεί 10 βήματα αναγωγής του `sum` + 9 προσθέσεις = 19 βήματα).
       - Στη συνέχεια: `square 55` $\to 55 * 55 = 3025$. (1 βήμα πολλαπλασιασμού).
       - **Σύνολο:** Το `sum` υπολογίζεται **μόνο μία φορά**. Πολύ αποδοτική στρατηγική!

    2. **Οκνηρή Αποτίμηση (Lazy / Normal-Order Evaluation χωρίς μοίρασμα/memoization):**
       - Πρώτα αναπτύσσεται ο εξωτερικός κανόνας της `square`:
         `square (sum [1:10])` $\to (\text{sum } [1:10]) * (\text{sum } [1:10])$.
       - Τώρα το `sum [1:10]` εμφανίζεται **δύο φορές**!
       - Αν δεν υπάρχει sharing (call-by-need), το άθροισμα $1+2+\dots+10$ θα υπολογιστεί δύο φορές, διπλασιάζοντας τον αριθμό των βημάτων αναγωγής.
       - Με **Call-by-Need (Lazy Evaluation with Graph Reduction / Sharing)**: Ο κόμβος `sum [1:10]` αποτιμάται μία φορά και η τιμή $55$ διαμοιράζεται και στους δύο παράγοντες, επιστρέφοντας $3025$.
       - **Συμπέρασμα αποδοτικότητας:** Η πρόθυμη αποτίμηση (ή η οκνηρή με μοίρασμα) είναι σαφώς πιο αποδοτική από την απλή οκνηρή αποτίμηση χωρίς memoization.
