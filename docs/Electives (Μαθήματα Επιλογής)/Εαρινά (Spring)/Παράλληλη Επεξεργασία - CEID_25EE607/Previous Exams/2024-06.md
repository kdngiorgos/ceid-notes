}

    ## Θέμα 1ο

    *Αξιοπιστία: μία λύση AI, δεν έχει αντιπαραβληθεί με δεύτερη · εμπιστοσύνη λύτη: υψηλή*

    **1.1** Σωστή επιλογή: **d. Αμοιβαίο αποκλεισμό**.  
    Οι μεταβλητές `pthread_mutex_t` είναι mutexes και χρησιμοποιούνται για αμοιβαίο αποκλεισμό κρίσιμων τμημάτων. Η επιλογή **c. Συγχρονισμός** είναι γενικότερα αληθής ως ευρύτερη κατηγορία, αλλά η ειδική λειτουργία του mutex είναι ο αμοιβαίος αποκλεισμός.

    **1.2** Σωστή επιλογή: **a. Μεταγλωττιστής**.  
    Το μοντέλο OpenMP περιλαμβάνει οδηγίες προς τον μεταγλωττιστή, βιβλιοθήκη χρόνου εκτέλεσης και μεταβλητές περιβάλλοντος. Ο ίδιος ο μεταγλωττιστής δεν είναι τμήμα του προγραμματιστικού μοντέλου.

    **1.3** Σωστή επιλογή: **c. Είτε ως νήματα επιπέδου χρήστη είτε ως νήματα επιπέδου πυρήνα**.  
    Το πρότυπο POSIX Threads δεν επιβάλλει συγκεκριμένη υλοποίηση· η υλοποίηση μπορεί να χρησιμοποιήσει νήματα χρήστη ή πυρήνα.

    **1.4** Σωστή επιλογή: **b. Κατανεμημένης μνήμης**.  
    Το MPI σχεδιάστηκε κυρίως για συστήματα κατανεμημένης μνήμης, όπου οι διεργασίες επικοινωνούν με μηνύματα.

    **1.5** Σωστή επιλογή: **b. Κάνει το πρόγραμμα MPI πιο ευανάγνωστο και πιο αποτελεσματικό στη μεταφορά δεδομένων**.  
    Οι συλλογικές συναρτήσεις μπορούν να υλοποιηθούν βελτιστοποιημένα από τη βιβλιοθήκη MPI και απλοποιούν τον κώδικα σε σχέση με χειροκίνητη επικοινωνία point-to-point.

    *(Η εικόνα `2024-06-30_11.15.34.png` επαναλαμβάνει την ερώτηση 1.5· δεν λύνεται ξανά.)*

    **1.6** Σωστή επιλογή: **c. 6**.  
    Με `reduction(+:test_var)` κάθε νήμα παίρνει ιδιωτικό αντίγραφο της `test_var` αρχικοποιημένο στην ταυτοτική τιμή της πρόσθεσης, δηλαδή $0$. Κάθε νήμα προσθέτει το `omp_get_thread_num()` του. Για 4 νήματα με αριθμούς $0,1,2,3$:
    \[
    0+1+2+3=6.
    \]
    Στο τέλος τα ιδιωτικά αποτελέσματα συνδυάζονται με πρόσθεση, άρα η τελική τιμή είναι $6$.

    ## Θέμα 2ο

    *Αξιοπιστία: μία λύση AI, δεν έχει αντιπαραβληθεί με δεύτερη · εμπιστοσύνη λύτη: υψηλή*

    **Παραλληλοποίηση της `find_max_and_pos` με OpenMP**

    Μια καλή λύση είναι κάθε νήμα να υπολογίζει τοπικό μέγιστο και θέση και στο τέλος να γίνεται συγχώνευση σε κρίσιμο τμήμα. Έτσι αποφεύγεται κρίσιμο τμήμα σε κάθε επανάληψη.

    ```c
    void find_max_and_pos(int *A, int N) {
        int max_val = A[0];
        int max_pos = 0;

        #pragma omp parallel
        {
            int local_max = A[0];
            int local_pos = 0;

            #pragma omp for
            for (int i = 1; i < N; i++) {
                if (A[i] > local_max ||
                    (A[i] == local_max && i < local_pos)) {
                    local_max = A[i];
                    local_pos = i;
                }
            }

            #pragma omp critical
            {
                if (local_max > max_val ||
                    (local_max == max_val && local_pos < max_pos)) {
                    max_val = local_max;
                    max_pos = local_pos;
                }
            }
        }

        printf("max value = %d at position %d\n", max_val, max_pos);
    }
    ```

    Αιτιολόγηση:  
    - Κάθε νήμα διατρέχει το δικό του τμήμα του πίνακα λόγω του `#pragma omp for` και κρατά τοπικές μεταβλητές `local_max`, `local_pos`, άρα δεν υπάρχει data race στον υπολογισμό.  
    - Η αρχικοποίηση `local_max = A[0]`, `local_pos = 0` είναι ασφαλής γιατί το $A[0]$ είναι έγκυρο υποψήφιο μέγιστο.  
    - Στο τέλος, ένα μόνο `#pragma omp critical` συγχωνεύει τα τοπικά αποτελέσματα στα κοινά `max_val`, `max_pos`.  
    - Η συνθήκη ισοπαλίας `local_pos < max_pos` διατηρεί τη θέση της πρώτης εμφάνισης του μεγίστου, όπως κάνει και ο αρχικός σειριακός κώδικας.  

    **2.2**  
    α. Ο κώδικας εκτυπώνει:
    ```text
    16.000000
    ```
    β. Αρχικά κάθε διεργασία έχει `data = rank`. Η `MPI_Bcast(..., root=2, ...)` μεταδίδει την τιμή της διεργασίας με rank $2$, δηλαδή `data = 2.0`, σε όλες τις 4 διεργασίες. Στη συνέχεια η `MPI_Allreduce` με πράξη `MPI_PROD` υπολογίζει το γινόμενο της ίδιας τιμής `2.0` πάνω και στις 4 διεργασίες:
    \[
    2.0 \cdot 2.0 \cdot 2.0 \cdot 2.0 = 2^4 = 16.0.
    \]
    Το αποτέλεσμα είναι ίδιο σε όλες τις διεργασίες, άρα η rank $1$ τυπώνει `16.000000`.

    ## Θέμα 3ο

    *Αξιοπιστία: μία λύση AI, δεν έχει αντιπαραβληθεί με δεύτερη · εμπιστοσύνη λύτη: υψηλή*

    **α. Πιθανά προβλήματα**

    1. **Data race στο `counter`:** Η εντολή `counter += do_work();` δεν είναι ατομική. Πολλά νήματα μπορεί να διαβάσουν ταυτόχρονα την ίδια τιμή του `counter`, να προσθέσουν και να γράψουν πίσω, χάνοντας ενημερώσεις.  
    2. **Λανθασμένη τελική εκτύπωση:** Η `main` τυπώνει το `counter` χωρίς να περιμένει να τελειώσουν τα νήματα με `pthread_join`. Μπορεί να εκτυπώσει πριν ολοκληρωθούν όλοι οι υπολογισμοί.  
    3. Επειδή η `do_work()` διαρκεί αρκετό χρόνο, δεν πρέπει να καλείται μέσα σε κρίσιμο τμήμα αν δεν είναι απαραίτητο· αρκεί να προστατευθεί η πρόσθεση στο `counter`.

    **β. Διορθωμένος κώδικας**

    ```c
    #include <stdio.h>
    #include <pthread.h>

    extern float do_work(); // implemented elsewhere

    float counter = 0;
    pthread_mutex_t counter_mutex = PTHREAD_MUTEX_INITIALIZER;

    void *func(void *arg)
    {
        for (int i = 0; i < 10; i++) {
            float val = do_work();   // εκτός κρίσιμου τμήματος

            pthread_mutex_lock(&counter_mutex);
            counter += val;
            pthread_mutex_unlock(&counter_mutex);
        }

        return NULL;
    }

    int main(int argc, char *argv[]) {
        pthread_t id[4];

        for (int i = 0; i < 4; i++)
            pthread_create(&id[i], NULL, func, NULL);

        for (int i = 0; i < 4; i++)
            pthread_join(id[i], NULL);

        printf("counter=%f\n", counter);
        return 0;
    }
    ```

    Αιτιολόγηση: Το mutex προστατεύει την ανάγνωση-τροποποίηση-εγγραφή της κοινής μεταβλητής `counter`, άρα δεν χάνονται ενημερώσεις. Η `pthread_join` εξασφαλίζει ότι η `main` τυπώνει το τελικό αποτέλεσμα αφού ολοκληρωθούν όλα τα νήματα.
